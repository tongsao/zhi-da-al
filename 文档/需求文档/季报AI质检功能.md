# 季报 AI 质检功能需求文档

> 版本：v1.0 ｜ 日期：2026-10-18
> 定位：接收上游信披中心推送的季报披露文件与结构化数据，自动校验关键字段一致性，替代人工逐条核对
> 状态：需求已评审确认，待开发

---

## 1. 背景与目标

### 1.1 背景

信披中心系统会向本系统推送各项目的季报披露文件（PDF）及对应的结构化数据。目前这些信息的核验完全依赖人工：业务人员需要打开 PDF、逐项与台账数据比对披露日期、金额、披露人等字段，工作量大、效率低，且人工核对容易遗漏差异。

### 1.2 目标

1. 接收并保存上游推送的季报披露文件与结构化数据；
2. 用 Agent 读取 PDF 并抽取关键字段，自动与业务数据比对；
3. 前端页面展示校验结果与差异明细，业务人员可一键定位不一致项；
4. 上游修正重新推送后，系统生成新的待校验记录，业务可快速一键复检并更新校验状态，减少人工工作量、提高业务效率。

---

## 2. 范围

### 2.1 本期包含（P0）

- 上游结构化数据接入与保存
- 上游 PDF 披露文件接入与保存
- 手动触发单条校验
- 校验字段抽取与规则比对
- 校验结果列表、明细展示
- 校验规则配置（开关）
- 不一致后的复检闭环

### 2.2 本期不包含

- 校验结果回传给上游系统（等待后续需求优化）
- 校验规则的在线新增/编辑（规则由开发预置，业务仅可开关）
- 自动触发校验（文件入库后不自动校验）

---

## 3. 核心流程与数据模型

### 3.1 端到端流程

```
上游信披中心
   │
   ├─ ① 推送结构化数据（project_id、项目名称、年、月、季度类型、金额、披露人、创建日期）
   ├─ ② 推送季报披露 PDF 文件
   ▼
本系统：文件与结构化数据均落库保存，两者通过 project_id 关联
   │
   ├─ ③ 业务人员在页面点击「开始校验」（手动触发，单条）
   ▼
异步校验：
   读取 PDF → 抽取字段（披露日期、金额、披露人、公告标题）
   → 按启用的规则逐项比对 → 结果落库
   ▼
前端展示：校验列表（按项目聚合）+ 明细（逐字段 PDF值 vs 表值 vs 结果）
   │
   ├─ 一致 → 流程结束
   ▼
不一致 → 业务人员到上游系统检查修正 → 重新推送同名 PDF 文件
   → 系统按文件名生成一条新的**待校验**记录（历史记录保留）
   → 业务人员对最新记录点击「开始校验」→ 完成复检 → 更新校验状态
```

### 3.2 核心对象

| 对象 | 说明 |
|---|---|
| 季报项目 | 上游推送的结构化数据，含 project_id、项目名称、年、月、季度类型、金额、披露人、创建日期；project_id 为全局唯一标识 |
| 披露文件 | 上游推送的季报披露 PDF，与项目通过 project_id 关联；文件名为合规披露文件，严格不变 |
| 校验记录 | 一次校验动作的完整留痕：被校验文件、被比对数据、各字段抽取值与比对结果、整体状态、校验时间 |
| 校验规则 | 开发预置的比对规则（字段 + 比对方式 + 是否启用），业务在页面开关 |

### 3.3 校验记录状态机

```
待校验 ──触发校验──▶ 校验中 ──完成──▶ 一致
                          │          不一致
                          └──异常──▶ 校验异常
```

- **待校验**：文件已入库、尚未发起校验
- **校验中**：异步校验执行中
- **一致**：所有启用的规则均比对通过
- **不一致**：任一启用的规则比对不通过（含字段缺失）
- **校验异常**：PDF 解析失败、字段抽取失败等技术问题（区别于业务不一致，单独标记）

状态流转约束：

| 当前状态 | 允许动作 | 结果状态 |
|---|---|---|
| 待校验 | 手动触发校验 | 校验中 |
| 校验中 | 不可再次触发 | — |
| 一致 / 不一致 / 校验异常 | 重新推送同名文件后生成新待校验记录，业务手动触发 | 校验中 |
| 一致 / 不一致 / 校验异常 | 手动再次触发 | 校验中 |

## 4. 功能需求

### 4.1 上游结构化数据接入

**目的**：接收上游推送的季报项目结构化数据，落库保存，作为后续校验的比对基准。

**触发**：上游信披中心调用本系统提供的推送接口，携带一条季报项目数据。

**处理规则**：
1. 以 project_id 为唯一键；同一 project_id 重复推送时，更新该条数据为最新内容；
2. 字段清单：project_id、项目名称、年、月、季度类型（一/二/三/四）、金额、披露人、创建日期；
3. 金额以「元」为单位的标准数值保存（上游如以万元/亿元推送，由开发按约定换算后入库）；
4. 数据校验：project_id 必填、年/月/季度类型必须合法（月份 1-12、季度类型 一~四）、金额必须为非负数值。

**结果与状态变化**：结构化数据保存成功，可被校验流程读取；project_id 与已入库的披露文件自动建立关联。

**异常**：字段缺失或非法时返回错误，不写入；上游可修正后重新推送。

### 4.2 上游披露文件接入

**目的**：接收上游推送的季报披露 PDF 文件，保存文件本体与文件信息，作为校验的抽取对象。

**触发**：上游信披中心调用本系统提供的文件推送接口，上传一份 PDF。

**处理规则**：
1. 支持 PDF 文字版（无扫描件 OCR 场景）；
2. 文件信息记录：文件名、文件路径、文件类型、关联 project_id、入库时间；
3. 文件名与结构化数据推送相互独立，通过 project_id 关联；同名文件重复推送视为**修正重推**，保存为一条新的待校验记录，历史记录保留（见 4.7）；
4. 文件大小、格式合法性校验由开发按现有上传链路约定执行。

**结果与状态变化**：文件落库保存，新增一条状态为「待校验」的校验记录；若新文件名与某条历史校验记录关联文件同名，则该新记录标记为**复检**来源（关联到原记录），供列表页区分展示，不自动执行校验。

**异常**：文件损坏、非 PDF 格式时拒绝入库并返回错误。

### 4.3 手动触发校验

**目的**：业务人员对已入库的披露文件发起一次校验。

**触发**：业务人员在校验列表页对「待校验 / 一致 / 不一致 / 校验异常」状态的记录点击「开始校验」。

**处理规则**：
1. 校验为**异步执行**，触发后立即返回，前端通过轮询获取进度与结果；
2. 单次只校验一条记录，不可并发触发同一条；
3. 校验时读取该条校验记录关联的文件（按 file_path），与该项目当前的结构化数据比对；
4. 校验只读取启用的规则（见 4.6）。

**结果与状态变化**：校验记录状态由「待校验」变为「校验中」，完成后变为「一致 / 不一致 / 校验异常」。

**异常**：文件已被删除或结构化数据缺失时，触发失败并提示原因。

### 4.4 PDF 字段抽取

**目的**：由 Agent 读取 PDF 文件内容，抽取待校验字段的取值。

**触发**：校验流程进入抽取阶段。

**处理规则**：
1. Agent 读取 PDF 全文，抽取以下字段：披露日期（年、季度）、金额、披露人、公告标题；
2. 抽取结果以结构化键值返回；无法从 PDF 中提取到某字段时，明确标记该字段「未提取到」，而非猜测填充；
3. 抽取结果在落库前可被业务人员在校验明细页查看原始取值与说明。

**结果与状态变化**：抽取结果进入比对环节。

**异常**：PDF 无法解析、抽取流程报错时，校验记录标记为「校验异常」，原因写明具体错误。

### 4.5 规则比对

**目的**：按启用的规则，将 PDF 抽取值与该项目的业务数据做一致性比对。

**触发**：字段抽取完成后自动执行。

**处理规则**：四条规则如下（每条规则独立启用/停用，比对口径见 5.1）。

| 字段 | PDF 侧取值 | 比对基准（业务数据） | 一致判定 |
|---|---|---|---|
| 披露日期 | 从 PDF 抽出的年份 + 季度 | 该项目的年 + 季度类型 | 年、季度均一致 |
| 金额 | 从 PDF 抽出的金额 | 该项目的金额 | 统一换算为「元」后一致（容差见 5.1） |
| 披露人 | 从 PDF 抽出的披露人 | 该项目的披露人 | 归一化处理后一致 |
| 公告标题 | 从 PDF 抽出的标题 | 文件名 | 精确一致 |

**结果与状态变化**：
- 所有启用规则一致 → 整体状态「一致」；
- 任一启用规则不一致或字段缺失 → 整体状态「不一致」，明细中写明不一致原因；
- 触发校验时若无任何启用的规则，则**拒绝触发**并提示「请先启用至少一条校验规则」，记录状态保持原状（不进入校验中）。

### 4.6 校验规则配置

**目的**：业务人员控制各条校验规则的启用状态，规则本体由开发预置。

**触发**：业务人员在规则配置页打开/关闭开关。

**处理规则**：
1. 规则表为**全局一套**，不分项目、不分文件类型；
2. 每条规则包含：字段名、比对方式、是否启用；
3. 业务仅可切换「是否启用」，不可修改比对方式与字段定义；
4. 规则启用状态在后续所有校验动作中即时生效。

**结果与状态变化**：开关状态保存，影响后续校验的比对范围；不影响已完成的校验记录。

### 4.7 不一致后的复检闭环

**目的**：业务人员在上游修正后重新推送文件，系统生成新的待校验记录，由业务一键复检，更新校验状态。

**触发**：上游重新推送与某条历史校验记录**同名**的 PDF 文件。

**处理规则**：
1. 新文件按文件名匹配历史校验记录（文件名严格不变，此为合规披露文件的约定）；
2. 匹配成功后生成一条新的校验记录，状态「待校验」，并在记录中标记**复检来源**（关联到被复检的历史记录），由业务在校验列表页点击「开始校验」完成复检；
3. 历史校验记录全部保留，页面以最近一次校验结果为主展示；
4. 文件名无法匹配任何历史记录时，按普通新文件入库处理，生成普通待校验记录。

**结果与状态变化**：生成一条新的待校验记录；业务手动触发后状态流转 校验中 → 一致 / 不一致 / 校验异常。

**异常**：新文件解析失败等，复检记录标记「校验异常」。

### 4.8 校验结果展示

**目的**：业务人员查看校验结果与差异明细，快速定位不一致项。

**触发**：进入校验页面。

**处理规则**：

**校验列表页**：
1. 按项目聚合展示，每行一个项目的最新校验记录；
2. 展示：项目名称、关联文件名、最新校验状态、校验时间、各字段一致性摘要；
3. 支持按状态（一致/不一致/校验异常/待校验）筛选、按时间排序；
4. 每行提供「开始校验」（对未校验或需复检记录）操作。

**校验明细页**：
1. 进入后展示该次校验的逐字段明细；
2. 每个字段展示：PDF 抽取值、业务数据值、一致/不一致结果、不一致原因；
3. 字段缺失时展示「未提取到」并附原因；
4. 不一致整条记录高亮，业务人员可据此到上游系统核对。

**结果与状态变化**：页面为只读展示；触发校验、复检的状态变化实时反映到列表。

## 5. 共享规则与例外

### 5.1 四条校验规则的比对口径

| 规则 | 归一化/换算规则 | 一致性判定 | 默认容差 |
|---|---|---|---|
| 披露日期 | 从 PDF 抽取「年份 + 季度」（如 2026 年三季度）；支持中文/阿拉伯数字表述 | 与业务数据的年、季度类型完全一致 | 无容差 |
| 金额 | 双方统一换算为「元」（如「1.2亿元」→ 120,000,000 元；去除千分位、货币符号），支持中文大写数字与小数 | 换算后差值绝对值 ≤ 容差 | ±0.01 元（业务可配） |
| 披露人 | 去除首尾空格、去除「股份有限公司 / 有限公司」等后缀后比对 | 归一化后完全一致 | 无容差，不做别名模糊匹配 |
| 公告标题 | 不做归一化，精确比对（含标点） | 完全一致 | 无容差 |

> 金额容差为可配置项，默认 ±0.01 元；业务在规则配置中可按需调整。

### 5.2 字段缺失处理

- PDF 中未提取到某字段：该字段按「不一致」处理，原因写明「PDF 中未提取到该字段」；
- 业务数据（表）中某字段为空：该字段按「不一致」处理，原因写明「业务数据中该字段为空」；
- 字段缺失不归入「校验异常」，校验异常仅用于解析/抽取等技术故障。

### 5.3 历史记录与留痕

- 同一项目每轮校验生成一条独立校验记录，全部保留；
- 页面默认展示最近一次校验结果，历史记录可查；
- 每次校验记录包含：校验时间、被校验文件、抽取值、业务值、逐字段结果、整体状态、原因。

### 5.4 全局异常兜底

- 校验全程（解析、抽取、比对、落库）任一步失败，记录标记「校验异常」并写明原因，不影响其他项目的校验；
- 文件与结构化数据未同时到位时，提示业务数据不完整，无法发起校验。

## 6. 待确认项

| 编号 | 内容 | 影响 |
|---|---|---|
| 1 | 上游推送频率与单次数量（是否批量推送） | 决定接入接口是否需支持批量 |
| 2 | 金额在 PDF 中的常见书写形式（中文大写/阿拉伯/带单位） | 影响金额解析的覆盖度 |
| 3 | 一个 PDF 是否可能包含多个项目的披露内容 | 影响抽取与关联方式 |
| 4 | 校验列表是否需要权限控制（哪些人可触发/查看） | 影响页面权限设计 |
| 5 | 容差 ±0.01 元默认值的合理性（是否需按业务实际放大） | 影响金额比对结果 |

> 以上待确认项不影响本期核心功能开发，开发前由业务补充确认即可；确认前按文档当前描述实现。
