# 统一网关需求文档

> 版本：v1.0 ｜ 日期：2026-10-21
> 定位：为「智答」平台统一补齐模型网关、接口鉴权、访问限流、调用审计与费用护栏，并以未来开放外部接入为标准设计
> 状态：需求已评审确认，待开发

---

## 1. 背景与目标

### 1.1 背景

平台现状存在以下问题：

1. **无鉴权**：全部接口裸奔，任何网络可达者均可调用问答、评测触发、文件删除等接口；上游信披中心推送数据与文件也无身份校验；
2. **无限流**：问答、评测、上传接口均无频率限制，全量评测一次可阻塞服务数十分钟，模型调用费用缺少护栏；
3. **无审计**：无法追溯「谁、何时、调用了什么、耗时多久」，外部接入后无凭据可查；
4. **模型接入分散**：生成、改写、向量化三类模型调用散落在各业务模块初始化，缺少统一的超时、重试、降级与用量统计。

### 1.2 目标

1. 建立统一的调用方准入体系：平台前端用户走登录凭证，机器/第三方调用方走独立密钥；
2. 按调用方维度实施接口限流，阻断异常调用与成本失控；
3. 记录调用审计，支持事后追溯；
4. 收敛模型调用入口，提供超时重试、主备降级与每日用量护栏；
5. 上述能力以横切方式接入，**不与现有业务逻辑耦合，不影响 AI 质检及其余功能并行开发**。

## 2. 范围

### 2.1 本期包含（P0）

- 平台用户登录与登录态管理（预置管理员账号，首次登录强制改密）
- 用户管理（管理员创建业务员账号、重置密码、启停账号）
- API 密钥管理（创建、停用、轮换、过期、IP 白名单绑定）
- 接口身份识别：登录凭证 / API 密钥双轨，按路径区分准入要求
- 访问限流：按 IP / 用户 / 密钥维度，重操作单独配额
- 调用审计：调用落库、管理员查询、保留期自动清理
- 统一模型接入：模型调用收敛、超时重试、主备降级
- 模型每日用量限额与超限拦截
- 前端：登录页、强制改密页、用户管理页、密钥管理页、审计查询页、用量看板页、token 管理、401 统一处理、路由守卫、角色显隐

### 2.2 本期不包含

- 密钥自助申请/自助过期（密钥由管理员创建分发）
- 第三方开放文档与开发者门户（本期只接入信披中心一类机器调用方）
- 登录态自动续期（refresh token 机制）
- 对接企业统一认证（LDAP/SSO）
- 多租户 / 分布式部署下的网关能力（当前单机部署，限流先按内存实现）

**完成证据**：管理员可用预置账号登录、强制改密后创建业务员账号与密钥；信披中心凭密钥成功推送结构化数据与文件，且该调用可在审计中查询；无凭证或超限的请求被统一拒绝并提示。

**外部依赖**：信披中心推送请求需携带网关签发的密钥，需上游配合改造接入；本需求交付前端与网关侧能力，上游改造由信披中心侧完成。

## 3. 角色与权限模型

### 3.1 角色

| 角色 | 说明 |
|---|---|
| 管理员 | 预置账号 admin；拥有全部权限，含用户管理、密钥管理、审计查询、规则开关、评测触发、文档删除 |
| 业务员 | 由管理员创建；可问答、查看知识库、上传文档、触发单条质检；不可管理用户/密钥、不可触发评测、不可删除文档、不可改规则开关 |

### 3.2 权限矩阵

| 能力 | 管理员 | 业务员 | 机器调用方（密钥） |
|---|---|---|---|
| 知识库问答（含流式） | ✅ | ✅ | ❌（密钥权限按接口分组可配，本期信披中心不授予问答） |
| 上传文档 | ✅ | ✅ | ❌ |
| 删除文档 | ✅ | ❌ | ❌ |
| 触发评测 / 生成评估 | ✅ | ❌ | ❌ |
| 查看评测结果 | ✅ | ✅ | ❌ |
| 质检推送（结构化数据 / 文件） | ❌ | ❌ | ✅ |
| 质检结果查看、触发单条校验 | ✅ | ✅ | ❌ |
| 质检规则开关 | ✅ | ❌ | ❌ |
| 用户管理 / 密钥管理 / 审计查询 | ✅ | ❌ | ❌ |

> 权限矩阵以「接口分组」为最小粒度实现；具体哪些接口归属管理员由实现时映射确认，映射表保持与上表一致即可。

## 4. 核心流程

### 4.1 平台用户使用流程

```
访问平台 → 未登录时路由守卫拦截 → 登录页（用户名 + 密码）
   ├─ 首次登录（预置/被重置账号）→ 强制改密页（完成前仅可改密）→ 改密成功 → 登录态失效，重新登录 → 进入首页
   └─ 已改密登录 → 进入首页使用业务功能
        ├─ 管理员 → 可见并可用用户管理 / 密钥管理 / 审计 / 评测 / 规则配置 / 文档删除
        └─ 业务员 → 不可见不可用上述能力
任一业务请求 → 登录态校验 → 未登录/过期 → 统一跳登录页
```

### 4.2 机器调用方使用流程（信披中心）

```
管理员创建密钥 → 设置名称、绑定调用方 IP 白名单、可选过期时间 → 密钥明文仅创建时返回
   → 分发给上游 → 上游推送请求带密钥凭证
   → 网关校验：密钥有效？IP 在白名单？未过期？未停用？→ 通过 → 进入业务处理 → 审计落库
```

## 5. 功能需求

### 5.1 平台用户登录与登录态

**目的**：前端管理端用户凭账号密码登录，获取限时登录态。

**触发**：用户在登录页提交用户名与密码。

**处理规则**：
1. 登录凭证 = 用户名 + 密码；账号停用、密码错误、账号不存在均按统一提示处理（见下方异常）；
2. 密码错误连续 5 次后，该账号锁定 30 分钟（防止暴力尝试）；锁定仅影响新的登录尝试，不影响已登录会话继续使用 `[Assumption, TBD]`；
3. 登录成功后签发登录态，有效期 **12 小时**，过期后需重新登录；本期不提供到期前自动续期；
4. 登录态包含用户身份与角色，后续请求凭此识别调用方；
5. 密码强度规则与改密要求见 §7.2。

**结果与状态变化**：登录成功返回登录态，前端保存并在后续请求中携带；登录失败返回统一提示。

**异常**：密码错误、账号不存在、账号停用均统一返回「用户名或密码错误」，不区分具体原因（防止暴露账号是否存在）；首次登录未改密不属登录失败，登录成功后进入强制改密流程（见 5.2）；系统异常返回「系统繁忙，请稍后重试」。

### 5.2 预置账号与强制改密

**目的**：系统预置管理员账号开箱可用，同时避免预置弱口令长期存在。

**处理规则**：
1. 系统初始化时创建管理员账号 `admin`，初始密码 `123456`；
2. 首次登录成功后，系统强制要求修改初始密码：业务功能不可用，仅可访问改密能力；
3. 改密成功前（含退出再登录），仍处于强制改密状态，只能访问改密能力；此时访问其余业务接口，统一返回「需先修改密码」引导（认证本身有效，属凭证有效但功能受限，区别于未授权）；
4. 改密成功后解除强制改密状态，当前登录态失效，用户需用新密码重新登录；再次登录即为正常使用；
5. 管理员可为业务员账号重置密码，重置后的密码同样触发该账号下次登录强制改密；
6. 初始密码或重置密码仅用于首次激活，不改密不失效（即：允许长期停在改密页，但不允许绕过）。

### 5.3 用户管理

**目的**：管理员维护平台账号体系。

**触发**：管理员在「用户管理」页操作。

**处理规则**：
1. 管理员可创建业务员账号：用户名唯一、设定初始密码、默认状态启用；
2. 管理员可重置任意账号密码；重置后该账号下次登录强制改密；
3. 管理员可启用/停用账号；停用后该账号立即无法登录，已签发的登录态即刻失效；本期不提供账号物理删除（停用即不可用）；
4. 禁止停用最后一个启用状态的管理员账号（保证系统始终可管理）`[Assumption, TBD]`；
5. 业务员看不到用户管理入口。

**结果与状态变化**：账号增、停、重设即时生效。

### 5.4 API 密钥管理

**目的**：为机器/第三方调用方提供独立于用户登录的准入凭证。

**触发**：管理员在「密钥管理」页创建密钥。

**处理规则**：
1. 创建密钥需填写：名称、绑定 IP 白名单（必填，支持多个 IP）、可选过期时间；
2. 密钥明文**仅创建时返回一次**，之后系统不再展示；丢失只能关闭旧密钥重新创建；
3. 密钥可停用/启用；停用后立即失效，已下发请求立刻被拒绝；
4. 密钥可轮换：生成新密钥并同时使旧密钥失效（用于怀疑泄露时）；
5. 密钥支持设置过期时间，到期自动失效；
6. 密钥本地校验时只比对摘要，不保存明文。

**异常**：密钥无效、停用、过期、来源 IP 不在白名单时，均拒绝并返回统一未授权提示（不区分具体原因，避免暴露密钥状态给未授权方）`[Assumption, TBD]`。

### 5.5 接口身份识别与准入

**目的**：统一识别每个请求的调用方身份，按接口分组执行准入要求。

**处理规则**：
1. 同一路径同时支持两类调用方：平台用户携带登录态、机器调用方携带密钥，二者取其一即可通过；
2. **豁免路径**（不要求任何凭证）：登录接口、系统健康检查、首页；其余全部接口默认要求有效凭证；
3. **要求密钥准入的路径**：上游推送类接口（质检结构化数据推送、质检文件推送）只接受密钥调用，不接受用户登录态；
4. **要求管理员角色的接口分组**：用户管理、密钥管理、审计查询、评测触发、文档删除、规则配置（见 §3.2）；
5. 流式问答接口与普通问答接口采用相同的准入要求；
6. 身份识别、准入拦截均由网关层统一完成，业务接口自身不重复实现。

**异常**：缺少凭证、凭证无效/过期、超出角色权限，均返回统一未授权/无权限响应；被拒绝的请求同样记入审计。

### 5.6 访问限流

**目的**：按调用方维度限制调用频率，阻断异常调用并保护服务与模型费用。

**处理规则**（初始配额，上线后可按实际调整）：

| 接口分组 | 维度 | 配额 | 说明 |
|---|---|---|---|
| 问答（含流式、历史等常规问答接口） | 按 IP | 10 次/分钟 | 防止单源异常 |
| 问答 | 按用户 | 30 次/分钟 | 正常操作远低于此 |
| 问答 | 按密钥 | 30 次/分钟 | 与用户同档 `[Assumption, TBD]` |
| 评测触发 / 生成评估触发 | 按管理员用户 | 1 次/分钟 | 防止误触发全量评测（高成本操作） |
| 文件上传 | 按用户 / 按密钥 | 5 次/分钟 | 防止批量灌入 |
| 其余接口 | 按用户 / 按密钥 / 按 IP | 60 次/分钟 | 通用兜底配额 `[Assumption, TBD]` |

1. 限流在身份识别**之后**执行：优先按已识别身份配额，未识别时按 IP；
2. 超限请求返回统一「请求过于频繁」响应（429 类语义），并提示稍后重试；
3. 评测类接口的超限不影响已在进行中的任务；
4. 限流计数在服务重启后清零（单机内存实现，属可接受范围）。

### 5.7 调用审计

**目的**：记录每次调用，支持事后追溯与问题定位。

**处理规则**：
1. 到达网关的请求均记录一条审计：调用方类型（用户/密钥）、调用方标识、请求路径、方法、来源 IP、处理结果（成功/未授权/无权限/超限/异常）、耗时、时间；
2. 包括被拒绝的请求（凭证无效、权限不足、超限）；认证相关请求（登录、改密，含登录失败）必记；系统健康检查等内部探测请求不记录，避免高频探测刷审计数据；
3. 审计可查询：管理员按时间、调用方、接口、结果筛选，分页展示；业务员不可见审计能力；
4. 审计记录保留 **90 天**，到期自动清理；清理策略见 §7.4。

### 5.8 统一模型接入

**目的**：收敛生成、改写、向量化三类模型调用，提供统一的健壮性保障。

**处理规则**：
1. 模型调用统一走网关入口；业务侧模型实例的获取方式由「自行初始化」调整为「经网关入口获取」，业务处理逻辑本身不变；模型密钥与地址集中管理，不下沉到业务代码；
2. 每次调用带超时时间，超时触发重试：**指数退避重试，最多 3 次**；
3. 主模型连续失败时自动降级到备选模型（主备关系见配置，缺省配置下降级行为默认关闭 `[Assumption, TBD]`）；
4. 单类模型故障不影响其他模型（生成失败不影响向量化）；
5. 每次调用记录用量（输入 token、输出 token）与归属模型，见 5.9；
6. 模型层发生故障时返回统一错误形态，供业务层提示「模型服务暂不可用」；模型层错误与业务错误互不混淆。

### 5.9 模型用量与每日限额

**目的**：防止模型费用失控（当前全量评测单次消耗较大）。

**处理规则**：
1. 生成、改写、向量化三类模型用量统一累计，按自然日统计；
2. 设置**每日 token 总量限额**（全模型共用）；限额数值上线前由运维配置，见 §8；
3. 当日用量达到限额后，拦截后续**新发起**的模型调用，业务提示「当日模型用量已用尽」，次日自动恢复；已在进行中的任务（如进行中的评测）不受影响、继续完成；
4. 用量达标与超限时输出预警记录，预警通道见 §8 `[TBD]`；
5. 管理员可查看近 90 日用量趋势与当日限额使用情况（见 §6 用量看板）。

## 6. 前端要求

1. **登录页**：用户名 + 密码登录，错误提示友好（详见 5.1）；
2. **强制改密页**：首次登录/被重置密码后进入，完成前不可使用业务功能（详见 5.2）；
3. **token 管理**：登录态保存在前端，自动附加到所有业务请求（含流式请求）；退出登录即清除；
4. **401 统一处理**：任一请求返回未授权/登录态过期时，统一跳转登录页；
5. **路由守卫**：未登录不可访问业务页；登录后按角色控制页面可达性；
6. **角色显隐**：管理员专属菜单（用户管理、密钥管理、审计、评测、规则配置、文档删除入口按接口分组对应）仅管理员可见；业务员不可见；
7. **用户管理页**（管理员）：账号列表、创建业务员、重置密码、启停，见 5.3；
8. **密钥管理页**（管理员）：密钥列表、创建、启用/停用、轮换、过期设置，创建时展示一次明文，见 5.4；
9. **审计查询页**（管理员）：按时间/调用方/接口/结果筛选的审计列表，见 5.7；
10. **用量看板页**（管理员）：近 90 日模型用量趋势与当日限额使用情况，见 5.9。

## 7. 共享规则与例外

### 7.1 统一响应与提示

- 未授权、登录态过期、无权限、超限使用统一的响应语义；前端据此执行跳转或提示；
- 登录失败统一返回「用户名或密码错误」，不区分密码错误/账号不存在/账号停用；
- 密钥校验失败统一返回「未授权」，不区分无效/停用/过期/IP 不符。

### 7.2 密码规则

- 初始/重置密码由系统设定（强制定改密兜底）；
- 修改密码时校验强度：**至少 8 位，需同时包含字母与数字** `[Assumption, TBD]`；
- 改密后原登录态是否保持：改为**不保持**，需用新密码重新登录 `[Assumption, TBD]`。

### 7.3 登录态失效范围

- 停用账号 → 已签发登录态即刻失效；
- 密钥停用/过期 → 即刻拒绝；
- 12 小时自然过期 → 过期后首个请求被拒并提示重新登录。

### 7.4 数据保留与清理

- 审计记录保留 90 天自动清理；
- 用量统计保留最近 **90 天** `[Assumption, TBD]`，每日滚动保留当日累计值。

### 7.5 接入方式约束（与现有系统的关系）

- 网关能力以独立代码单元承载，与现有业务代码物理隔离，不修改现有业务模块内部逻辑；
- 模型收敛属例外改造：仅调整业务侧模型实例的获取方式为经统一入口，业务处理逻辑保持不变；
- 现有 AI 质检功能不受本需求影响，可并行开发、独立发布；
- 预置规则、初始数据等初始化行为需幂等，可重复启动。
